# Добей фразу

Быстрый MVP браузерной онлайн-игры для небольшой компании друзей. Игроки пишут начала фраз, добивают чужие фразы, голосуют за лучшую шутку и получают очки.

## Фичи

- комнаты по короткому коду из 4 символов;
- realtime через Socket.IO;
- настройки лобби: раунды, таймеры, анонимность, звуки, режим начал, режим раздачи, максимум игроков;
- ручные и автоматические начала фраз;
- режимы `каждый добивает чужую фразу` и `все добивают одну фразу`;
- авто-заполнение пропусков по таймеру;
- голосование без возможности голосовать за свою концовку;
- история лучших шуток;
- копирование шуток;
- простые звуки через Web Audio API без аудиофайлов;
- финальная таблица и смешные титулы.

## Технологии

- Node.js;
- Express;
- Socket.IO;
- обычный HTML, CSS и vanilla JavaScript;
- хранение данных только в памяти сервера.

## Локальный запуск

```bash
npm install
npm start
```

Открыть игру:

```text
http://localhost:3000
```

Для проверки открой несколько вкладок браузера: в первой создай комнату, в остальных войди по коду с другими никами, затем пройди полный раунд.

## Архитектура

Вариант A:

- Cloudflare Pages = только статический frontend из папки `public`;
- Render = Node.js + Express + Socket.IO backend;
- комнаты и состояние игры живут в памяти Render-сервера;
- базы данных и авторизации нет.

Серый IP игроков не мешает, потому что все игроки сами подключаются из браузера к публичному Render backend.

Данные пропадают после перезапуска Render-сервера, потому что база данных не используется.

## BACKEND_URL

В `public/client.js` есть настройка:

```js
const BACKEND_URL =
  location.hostname === "localhost" || location.hostname === "127.0.0.1"
    ? "http://localhost:3000"
    : "https://PASTE_RENDER_BACKEND_URL_HERE";
```

После деплоя backend на Render замени:

```text
https://PASTE_RENDER_BACKEND_URL_HERE
```

на реальный Render URL, например:

```text
https://dobey-frazu-server.onrender.com
```

## CORS

В `server.js` сейчас явно разрешены:

```js
[
  "http://localhost:3000",
  "http://localhost:5173",
  "https://exitserial.pages.dev"
]
```

Если Cloudflare Pages создает preview-домены, добавь их в `ALLOWED_ORIGINS`.

Для совсем временного MVP можно поставить `origin: "*"`, но нормальный вариант - указывать конкретные домены frontend.

## Деплой варианта A: Cloudflare Pages + Render

### 1. Backend на Render

1. Создай новый Web Service.
2. Подключи GitHub репозиторий с этим проектом.
3. Build command:

```bash
npm install
```

4. Start command:

```bash
npm start
```

5. Убедись, что сервер слушает `process.env.PORT`. В проекте уже используется:

```js
const PORT = process.env.PORT || 3000;
```

6. После деплоя скопируй Render URL.

### 2. Frontend на Cloudflare Pages

1. Открой Cloudflare Workers & Pages.
2. Выбери Pages.
3. Подключи GitHub репозиторий.
4. Для статического сайта укажи папку `public`.
5. Build command можно оставить пустым.
6. Output directory:

```text
public
```

### 3. Связать frontend с backend

В `public/client.js` замени:

```text
https://PASTE_RENDER_BACKEND_URL_HERE
```

на реальный Render backend URL.

### 4. Проверка после деплоя

1. Открой frontend на Cloudflare Pages.
2. Создай комнату.
3. Открой этот же сайт с другого устройства или в другом браузере.
4. Войди по коду комнаты.
5. Убедись, что игроки появляются в лобби и realtime-события работают.

## Локальное тестирование режимов

Проверь в нескольких вкладках:

- обычный режим с ручными началами;
- режим авто-начал;
- режим `все добивают одну и ту же фразу`;
- таймеры, включая значение `0`;
- анонимный режим и раскрытие авторов после голосования;
- копирование шуток;
- звуки при раскрытии и на финале;
- историю лучших шуток;
- финальные титулы;
- переход на следующий раунд;
- завершение игры после заданного количества раундов.
